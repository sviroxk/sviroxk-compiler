# Спецификация языка SC

Это единственное описание языка. Оно составлено по поведению компилятора `0.3.0`
и проверяется тестами: каждый пример ниже `test.sh` извлекает, компилирует и
запускает, а вывод сравнивает с блоком «вывод». Если документ расходится с кодом,
ошибка в документе, и тест это покажет.

Соглашение для примеров:
- блок `sc` — программа, за ним блок `text` с точным выводом;
- блок `stdin` между ними — то, что программа получает на вход;
- блок `sc-error` — программа, которая не должна компилироваться; блок `text`
  после неё содержит часть сообщения об ошибке.

## 1. Программа

Файл `.svx` — это последовательность объявлений и операторов. Код верхнего
уровня выполняется сверху вниз, отдельная функция `main` не нужна (имя `main`
занято). Комментарии: `// до конца строки`. Оператор заканчивается `;`.

```sc
// вывод
print("Привет, мир!");
print(42);
```
```text
Привет, мир!
42
```

Сборка и запуск: `./sc файл.svx > файл.ll`, затем `lli файл.ll` или `llc` и `clang`.
Код выхода компилятора: 0 — успех, 1 — синтаксическая ошибка, 2 — семантическая,
3 — внутренняя ошибка компилятора. Ошибка выполнения печатает в stderr
`SC runtime error: <что> at line L, column C` и завершает программу с кодом 1;
уже напечатанный вывод программы остаётся в stdout.
Ошибка компиляции печатается как `файл:строка:столбец: error[вид]: текст` со строкой
исходника и `^` под местом. Пропущенная `;` в конце строки указывается сразу после
последнего токена этой строки: `int x = 1` без `;` → `1:10: error[syntax]: ожидалась ';' после '1'`
(одна ошибка, следующая строка не разбирается как продолжение).

Вложенность блоков, скобок и унарных операторов — не больше 256 уровней (как
`-fbracket-depth` у clang); глубже — синтаксическая ошибка «слишком глубокая вложенность». В одной инструкции —
не больше 250000 бинарных операторов (`1 + 1 + …`); больше — ошибка «слишком длинное выражение».
Цепочка `if … else if …` — не больше 2500 звеньев `else if`; длиннее — ошибка
«слишком длинная цепочка else if».

## 2. Типы

| Тип | Короткое имя | Что это |
|---|---|---|
| `i8` `i16` `i32` `i64` | `short` = i16, `int` = i32, `long` = i64 | знаковые целые |
| `u8` `u16` `u32` `u64` | `byte` = u8, `ushort` = u16, `uint` = u32, `ulong` = u64 | беззнаковые целые |
| `f32` `f64` | `float` = f32, `double` = f64 | числа с плавающей точкой |
| `bool` | | `true` / `false` |
| `char` | | символ `'a'`, в арифметике ведёт себя как `u8` |
| `str` | `string` | строка |
| `ptr` | | указатель или динамический массив |
| `file` | | открытый файл |
| `Имя` (структура) | | объявляется через `struct` |
| `void` | | «нет значения», только тип результата функции |

Точные имена (`i32`, `f64` …) — основные, короткие — их алиасы.
Целые литералы по умолчанию имеют тип `i32` (если значение не помещается в
`i32` — тип `i64`), дробные — `f64`.
Литералы: `42`, `0x2A`, `0b101010`, `1_000`, `1.5`, `2e3`, `'a'`, `"текст"`.

## 3. Переменные

```sc
int a = 1;          // тип и значение
let b = 2;          // тип выводится из значения
let c: i64 = 3;     // let с явным типом
const d: int = 4;   // константа
int e = 5;  // старая форма объявления, работает так же
a = a + b;
a += c;             // составные: += -= *= /= %=
a++;
print(a + d + e);
```
```text
16
```

Имена видны в своём блоке `{ }` и во вложенных. Внутренний блок может объявить
то же имя заново (затенение). Использовать переменную до присваивания нельзя.

```sc-error
int x = 1;
int x = 2;
```
```text
повторное объявление 'x'
```

## 4. Операторы и политика целых

Арифметика `+ - * / % **`, целочисленное деление с округлением вниз `div`
(`-17 div 5` равно `-4`; `//` — всегда комментарий),
побитовые `& | ^ ~ << >>`, сравнения `< > <= >= == !=`, логические `&& || !`
(с коротким замыканием), тернарный `условие ? a : b`.
`-2 ** 2` равно `-(2 ** 2)`. `%` для дробных — остаток как `fmod` в C (знак
делимого): `-5.5 % 2.0` равно `-1.5`.
Сравнения не соединяются в цепочку (как в Rust): `1 < 2 < 3` — ошибка компиляции
«сравнения нельзя соединять в цепочку (a < b < c): результат сравнения — bool, а не число;
пишите a < b && b < c» у второго оператора; диапазон проверяется как `0 < x && x < 10`.

```sc
print(7 / 2);
print(7 % 3);
print(2 ** 10);
print(-2 ** 2);
print(17 div 5);
print(6 & 3);
print(1 << 4);
int v = 4;
print(v > 3 ? 10 : 20);
```
```text
3
1
1024
-4
3
2
16
10
```

```sc
f64 x = 5.5;
print(x % 2.0);
print(-5.5 % 2.0);
```
```text
1.500000
-1.500000
```

**Значение молча не портится.** Для целых:
- переполнение `+ - * **`, унарного минуса, `MIN / -1` — ошибка выполнения
  `integer overflow`;
- деление и остаток на ноль — `division by zero`;
- сдвиг на число вне `0..ширина-1` — `shift amount out of range`;
- если такое видно из констант, это ошибка компиляции;
- запись результата в узкий тип (`u8 x; x += 1;`) проверяет диапазон.

```sc
print(-9223372036854775807 - 1);
print(5000000000 * 2);
```
```text
-9223372036854775808
10000000000
```

```sc-error
print(2147483647 + 1);
```
```text
переполнение: значение константного выражения 2147483648 не помещается в тип 'int/i32'
```

```sc-error
int a = 5;
print(a / 0);
```
```text
деление на ноль
```

Арифметика над `i8`/`u8`/`i16`/`u16`/`char` выполняется в `i32`.

### Преобразования

Неявно разрешено только то, что не теряет значение: расширение целого той же
знаковости, беззнаковое → более широкое знаковое, `f32` → `f64`, любое целое →
`f64`, целое до 16 бит → `f32`. Константа, которая точно помещается в тип,
тоже разрешена (`u8 b = 200;`). Остальное требует явного приведения `(T) x`.
Явное приведение проверяет диапазон: константа вне `T` — ошибка компиляции,
значение во время выполнения — `value out of range for type 'T'`.

```sc
i64 big = 5000000000;
int small = 7;
i64 wide = small;
f64 f = 3.75;
print((int) f);
print(wide);
print((i64) big + 1);
u8 b = 200;
print(b);
```
```text
3
7
5000000001
200
```

```sc-error
i64 a = 1;
int b = a;
```
```text
нужно явное приведение
```

## 5. Условия и циклы

```sc
int x = 3;
if (x == 1) {
    print(1);
} else if (x == 3) {
    print(3);
} else {
    print(0);
}
int n = 0;
while (n < 2) { n += 1; }
print(n);
for i in 0..3 { print(i); }
for j in 1..=2 { print(j); }
int[] values = [5, 6];
for value in values { print(value); }
repeat (2) { print(9); }
loop {
    n += 1;
    if (n == 4) { break; }
    if (n == 3) { continue; }
}
print(n);
```
```text
3
2
0
1
2
1
2
5
6
9
9
4
```

`for i in a..b` — от `a` до `b - 1`, `a..=b` — включительно. `repeat (n)`
повторяет блок `n` раз. `loop` — бесконечный цикл, выход через `break` или `return`.
Условие — `bool` или целое (ноль — ложь). Код после `return`/`break`/`continue`
в том же блоке — ошибка компиляции.

## 6. Функции

```sc
fn int square(int x) { return x * x; }
fn void show(int x) { print(x); }
fn bool even(int n);                 // объявление без тела
fn bool odd(int n) { if (n == 0) { return false; } return even(n - 1); }
fn bool even(int n) { if (n == 0) { return true; } return odd(n - 1); }
show(square(5));
print(even(10));
```
```text
25
1
```

Без типа результата (`fn show(int x) { … }`) функция ничего не возвращает — то же,
что `fn void show(int x)`; `return значение;` в ней — ошибка компиляции.
Функцию можно вызвать до её определения. Объявление без тела должно совпадать
с определением по типам. Функция с результатом должна возвращать значение на
всех путях (бесконечный `loop` без `break` тоже считается). Вложенные функции,
перегрузка и имена встроенных функций (`max`, `sqrt` …) как имена своих функций
запрещены. Аргументы разделяются запятыми.

## 7. Структуры

```sc
struct Inner { int x = 0; }
struct Pair {
    int a = 1;
    Inner inner;
}
fn int sum(Pair p) { p.a = 100; return p.a + p.inner.x; }
Pair value = { a = 2; inner = { x = 0; }; };
value.inner.x = 5;
value.a += 1;
print(sum(value));
print(value.a);
```
```text
105
3
```

`struct Имя { поля }` объявляет структуру; поля могут иметь значения по умолчанию.
Переменная-структура: `Имя x;` или с инициализатором `Имя x = { поле = значение; };`.
Параметр-структура: `fn int f(Имя x)`.
В функцию структура передаётся копией. Рекурсивная структура (поле своего же типа) запрещена.

Функция может вернуть структуру (`fn Имя f(…)`). Результат кладётся в переменную
(`Имя x = f();`), присваивается (`x = f();`) или сразу передаётся в другую
функцию. `Имя y = x;` и `y = x;` — копия: изменение `y` не меняет `x`.

```sc
struct Point { int x = 0; int y = 0; }
fn Point shift(Point p, int dx) { p.x += dx; return p; }
Point a = { x = 1; y = 2; };
Point b = shift(a, 10);
Point c = b;
c.y = 5;
Point d = shift(shift(a, 1), 1);
print(a.x);
print(b.x);
print(b.y);
print(c.y);
print(d.x);
```
```text
1
11
2
5
3
```

Поля любых типов — как в C++ и Rust (D-016). Строка в поле принадлежит структуре:
литерал или переменная при записи копируются, результат `str()` и других функций
забирается; `p.name = …` освобождает прежнюю строку; поле `string` без значения —
пустая строка. Когда структура выходит из области (конец блока, `return`, `break`,
`continue`), строки её полей, в том числе во вложенных структурах, освобождаются
сами. `Имя y = x;`, `y = x;`, `y.inner = x.inner;` и передача в функцию — полная
копия: у копии свои строки. Поле `ptr` копирует только адрес, как ptr-переменная.

```sc
struct Tag { string label = "new"; }
struct Person { string name; int age = 0; Tag tag; }
fn int rename(Person p) { p.name = "Bob"; return len(p.name); }
Person ann = { name = "Ann"; age = 30; tag = { label = str(7); }; };
Person copy = ann;
copy.name = "Kate";
copy.tag.label = "copy";
print(ann.name);
print(ann.tag.label);
print(copy.name);
print(rename(ann));
print(ann.name);
```
```text
Ann
7
Kate
3
Ann
```

`return p;` для локальной структуры отдаёт её наружу без копии (строки полей
не освобождаются и не копируются); глобальная структура или поле возвращаются копией.
`Имя y = move(x);` (и `move(x)` в аргументе или `return`) переносит структуру
целиком, как строку (D-015): после этого `x` нельзя использовать до нового
присваивания. Результат функции, не положенный в переменную (`f(make());`,
`make();`), освобождается в конце оператора.

```sc
struct Person { string name; int age = 0; }
fn Person make(string n, int a) { Person p = { name = n; age = a; }; return p; }
fn Person older(Person p) { p.age += 1; return p; }
Person ann = make(str(7), 30);
Person moved = move(ann);
print(moved.name);
ann = older(make("Kate", 3));
print(ann.name);
print(ann.age);
```
```text
7
Kate
4
```

Поле `T[] имя;` (элементы — числа, `bool`, `char`) — растущий массив, который
принадлежит структуре (D-016, D-017): сначала пустой, методы и индекс как у
динамического массива (`p.scores.push(x)`, `p.scores[i]`, `p.scores.len()`),
освобождается сам вместе со структурой; копия структуры копирует массив целиком,
`move` и `return` переносят. Два слова (D-017): `p.scores.clear();` очищает, как в
C++ — `len()` = 0, `push` работает, чтение элемента — ошибка выполнения «вне границ»,
повторный `clear` безопасен (`clear()` есть и у динамических массивов-переменных).
`drop p.scores;` убирает, как в Rust: до нового присваивания списком
`p.scores = [...]` поле нельзя читать и менять, а всю `p` — копировать, передавать,
возвращать и переносить; повторный `drop` — ошибка компиляции. Целиком поле не
берётся; присвоить ему можно только список.

```sc
struct Stats { string name; int[] scores; }
Stats a;
a.scores.push(5);
a.scores.push(7);
Stats b = a;
b.scores[0] = 1;
print(a.scores[0] + a.scores[1]);
print(b.scores[0]);
a.scores.clear();
print(a.scores.len());
drop b.scores;
b.scores = [4, 5];
print(b.scores[1]);
```
```text
12
1
0
5
```

```sc-error
struct S { int[] a; }
S s;
drop s.a;
s.a.push(1);
```
```text
's.a' используется после drop (строка 3)
```

```sc-error
struct Person { string name = ""; }
Person a;
Person b = move(a);
print(a.name);
```
```text
'a' используется после move
```

Массив структур — статический массив (`Имя[] a = [ … ];`, §8). Элемент задаётся
литералом `{ … }`, вызовом функции или переменной (копия). `a[i].поле` (в том числе
вложенное `a[i].x.y`) читается и меняется (`=`, `+=` и др.; индекс вычисляется
один раз), `a[i] = f();` заменяет элемент, `Имя x = a[i];` — копия элемента,
`for p in a` перебирает копии элементов. Индекс проверяется, как у любого массива.
Элементы со строками и массивами в полях подчиняются D-016/D-017: элемент владеет
ими и освобождается вместе с массивом, `a[i] = q` и `Имя x = a[i]` — полные копии,
результат функции забирается без копии; `move(a[i])` — ошибка (переносится только
переменная). Методы поля-массива у элемента (`a[i].v.push(x)`) пока не поддерживаются.

```sc
struct Point { int x = 0; int y = 0; }
fn Point make(int x) { Point p = { x = x; y = x * 2; }; return p; }
Point origin;
Point[] pts = [{ x = 1; y = 2; }, make(5), origin];
pts[0].x += 10;
pts[2] = make(7);
Point copy = pts[1];
copy.y = 0;
print(pts.len());
print(pts[0].x);
print(pts[1].y);
for p in pts { print(p.x + p.y); }
```
```text
3
11
10
13
15
21
```

```sc-error
struct Point { int x = 0; }
Point[] pts = [{ x = 1; }];
pts[0].x = "один";
```
```text
поле ожидает тип 'int/i32', получен 'str'
```

Растущий массив структур (1.3) — `Имя[] a = new Имя[n];` (`n` элементов со значениями
полей по умолчанию): `a.push(q)` добавляет копию `q`, `a.push(f())` забирает
результат без копии; `a[i].x` чтение и запись, `a[i] = q`, `Имя r = a[i]` — копии;
`len`, `cap`, `resize`, `clear` (строки и массивы полей уходящих элементов
освобождаются, новые получают значения по умолчанию); вместе с массивом
освобождается всё, что принадлежит элементам. Передача в функцию (`fn int f(Имя[] list)`),
возврат (`fn Имя[] team()`), `Имя[] b = a`, `move(a)` — как у массива чисел (§8):
копия полная, перенос без копии. `pop()` у массива структур пока нет.

```sc
struct Person { string name = "?"; int age = 18; }
fn Person person(string name, int age) { Person p; p.name = name; p.age = age; return p; }
fn int oldest(Person[] list) {
    int best = 0;
    for i in 0..list.len() { if (list[i].age > best) { best = list[i].age; } }
    return best;
}
Person[] people = new Person[1];
people.push(person("Ann", 30));
Person bob = { name = "Bob"; age = 41; };
people.push(bob);
bob.name = "Robert";
people[0].name = "Kim";
print(people.len());
print(people[0].name);
print(people[0].age);
print(people[2].name);
print(oldest(people));
```
```text
3
Kim
18
Bob
41
```

```sc-error
struct Person { string name = "?"; }
Person[] people = new Person[0];
people.push("Ann");
```
```text
элемент массива ожидает тип 'Person'
```

**Задача 11 «набор людей»** — записи хранятся одним массивом структур, без
параллельных массивов: вложенная запись (`home`), строка и растущий массив в полях,
возврат структуры из функции, передача элемента в функцию (копия), поиск, изменение
и полная копия элемента. Вся память освобождается сама (D-016/D-017).

```sc
struct Address { string city = ""; int zip = 0; }
struct Person { string name = ""; int age = 0; Address home; int[] scores; }

fn Person make(string name, int age, string city) {
    Person p = { name = name; age = age; home = { city = city; }; };
    return p;
}

fn int total(Person p) {
    int sum = 0;
    for i in 0..p.scores.len() { sum += p.scores[i]; }
    return sum;
}

fn Person older(Person p, int years) {
    p.age += years;
    return p;
}

Person bob = make("Bob", 41, "Omsk");
bob.scores.push(7);
Person[] people = [make("Ann", 30, "Tver"), bob, { name = "Eve"; age = 25; home = { city = "?"; }; }];
people[2].home.city = "Kazan";
people[2].home.zip = 420000;
people[0].age += 1;
people[1] = older(people[1], 2);

int found = -1;
for i in 0..people.len() {
    if (people[i].name == "Eve") { found = i; }
}
print(found);

Person copy = people[0];
copy.name = "Ann-2";
copy.scores.push(5);
copy.scores.push(6);
print(people[0].name);
print(copy.name);
print(total(copy));
print(total(people[1]));

for p in people {
    print(p.name);
    print(p.age);
    print(p.home.city);
}
```
```text
2
Ann
Ann-2
11
7
Ann
31
Tver
Bob

Omsk
```

## 8. Массивы

Статический массив имеет фиксированную длину; индекс проверяется
(константный — при компиляции, остальные — при выполнении). Константа в
литерале массива должна помещаться в тип элемента.

```sc
int[] a = [1, 2, 3];
a[0] = 10;
a[1] += 5;
print(a[0] + a[1] + a[2]);
```
```text
20
```

```sc-error
u8[] b = [10, 300];
```
```text
элемент массива 300 вне диапазона типа 'byte/u8'
```

Динамический массив создаётся `new T[n]`: длина `n`, элементы равны нулю.
Отрицательный `n` (в `new` и `resize`) или размер, под который не хватает памяти, —
ошибка выполнения. `resize(n)` с большей длиной заполняет новые элементы нулями.
Методы: `push(x)`, `pop()` (возвращает элемент, у пустого — 0), `resize(n)`,
`clear()` (длина 0, память остаётся), `len()`, `cap()`. У статического массива есть только `len()` и `cap()` — оба
возвращают его длину.
Память динамического массива возвращается сама в конце блока, где он объявлен
(на `return`, `break`, `continue` тоже), как у массива в поле структуры (§7, D-018);
`drop v;` (или `del v;`) возвращает её раньше.

```sc
ptr v = new int[2];
v[0] = 4;
v.push(7);
print(v.len());
print(v.pop());
print(v[0]);
drop v;
```
```text
3
7
4
```

Растущий массив можно объявить и как `int[] v = new int[2];`. Он передаётся в
функцию и возвращается из неё (D-018); параметр и результат пишутся как поле
структуры: `int[] v`, `fn int[] имя(…)`. Функция получает копию (как `vector` в
C++) — массив вызывающего не меняется; `move(a)` отдаёт массив насовсем, без копии,
и дальше `a` нельзя использовать до нового присваивания (как в Rust). Так же
`int[] b = a;` и `b = a;` — копия, `int[] b = move(a);` — перенос; обычный массив
(`int[] s = [1, 2];`) отдаётся копией. `return v` локального массива или параметра
отдаёт его без копии; результат, не положенный в переменную, освобождается в конце
оператора. Параметр `ptr` длину не знает: растущий массив в него не передаётся.

```sc
fn i64 total(int[] v) {
    i64 sum = 0;
    for i in 0..v.len() { sum += v[i]; }
    v.push(100);
    return sum;
}
fn int[] squares(int n) {
    int[] r = new int[0];
    for i in 0..n { r.push((i + 1) * (i + 1)); }
    return r;
}
int[] a = squares(3);
print(total(a));
print(a.len());
int[] b = move(a);
print(b[2]);
int[] s = [5, 6];
print(total(s));
```
```text

3
9
11
```

```sc-error

print(a.len());
```

### Окно на часть массива (срез)

Функции можно отдать часть массива без копии — окно (D-018, решение владельца
«оба способа»). Срез пишется двумя способами, как в Rust и как в C++:
`v[1..4]` — элементы с 1 по 3 (конец не входит, как в `for i in 0..3`),
`slice(v, 1, 3)` — начало и количество; это одно и то же окно. Параметр-окно тоже
пишется двумя способами, это один тип: `fn int sum(int[..] part)` и
`fn int sum(slice int[] part)`. В такой параметр можно отдать и массив целиком
(`sum(v)`) — тоже без копии; годится растущий и обычный массив, массив структур,
другое окно (`part[1..part.len()]`).

Функция читает и меняет элементы окна (`part[i] = …`) — меняется массив
вызывающего, он остаётся у хозяина. Длину окна менять нельзя (`push`, `pop`,
`resize`, `clear`), как и `drop`, `move` и присваивание окну другого массива — ошибки
компиляции. `int[] c = part;` и `return part` из `fn int[] f(int[..] part)` дают
свою копию. Окно живёт только на время вызова: положить срез в переменную нельзя
(время жизни — задача 5.2). Индекс в окне проверяется по длине окна; срез за
краями массива (`v[1..5]` у массива из трёх, начало больше конца, отрицательное
начало) — ошибка выполнения `slice out of bounds`. Пример — `examples/slice_window.svx`.

```sc
fn int sum(int[..] part) {
    int s = 0;
    for i in 0..part.len() { s += part[i]; }
    return s;
}
fn void twice(slice int[] part) {
    for i in 0..part.len() { part[i] = part[i] * 2; }
}
int[] v = [1, 2, 3, 4, 5];
print(sum(v[1..4]));
print(sum(slice(v, 1, 3)));
twice(v[0..2]);
print(v[1]);
print(sum(v));
```
```text
9
9
4
18
```

```sc-error

```
```text
'part' — окно на часть чужого массива: длину окна менять нельзя
```

### Обход массива: `for x in v`

`for x in v` перебирает по порядку копии элементов любого массива: обычного,
растущего, окна (`int[..] part`), массива структур. `x` — своя копия: её изменение
массив не меняет; менять элементы — через индекс (`for i in 0..v.len() { v[i] = …; }`),
это внутри цикла разрешено. Длину `v` и сам `v` внутри такого цикла менять нельзя —
`push`, `pop`, `resize`, `clear`, `drop`, присваивание `v = …` — ошибка компиляции
(как в Rust; в C++ это неопределённое поведение). После цикла — снова можно.
Пример — `examples/for_each_grow.svx`.

```sc
fn int sum(int[..] part) {
    int t = 0;
    for x in part { t += x; }
    return t;
}
int[] v = new int[0];
for i in 1..=3 { v.push(i * 10); }
for x in v { print(x); }
print(sum(v[1..3]));
v.push(5);
print(v.len());
```
```text
10
20
30
50
4
```

```sc-error
int[] v = new int[2];
for x in v { v.push(x); }
```
```text

```

## 9. Указатели и `null`

`&x` — адрес переменной (для строки — `data(s)`, §11), `*p` — значение по адресу, `null` — пустой указатель
(допустим только для `ptr`). Разыменование `null` — ошибка выполнения
`null pointer dereference`. Указатели сравниваются только через `==` и `!=`.
Вернуть из функции адрес её локальной переменной или параметра (`return &x;`,
а также `ptr p = &x; return p;`) — ошибка компиляции.

```sc
int x = 5;
ptr p = &x;
*p = 9;
print(x);
ptr q = null;
if (q == null) { print(1); }
```
```text
9
1
```

```sc-error
int a = null;
```
```text
null и указатели допустимы только для типа ptr
```

## 10. `defer` и `drop`

`defer операция;` выполняет операцию при выходе из текущего блока, в обратном
порядке. При `return` сначала вычисляется значение, затем выполняются `defer`.
Внутри `defer` нельзя объявлять переменные и делать переходы.

`drop x;` освобождает динамический массив раньше конца блока (сам он освобождается
в конце блока, §8) или закрывает файл. После `drop`
имя использовать нельзя, повторный `drop` — ошибка компиляции, как и `drop`
внешней переменной внутри цикла или функции.

```sc
fn int f(int x) {
    ptr v = new int[2];
    defer drop v;
    defer print(1);
    v[0] = x;
    return v[0] + 1;
}
print(f(4));
```
```text
1
5
```

```sc-error
ptr v = new int[2];
drop v;
print(v[0]);
```
```text
'v' используется после drop (строка 2)
```

`del p;` освобождает память по указателю (ручной режим). Как после `drop`, имя `p`
дальше использовать нельзя, повторный `del p;` — ошибка компиляции; новое
присваивание `p = new int[2];` снова делает имя пригодным. Второе имя на ту же
память (`ptr q = p;`) не отслеживается.
Статический массив (`int[] a = [1, 2];`) освобождается сам: `del a;` для него —
ошибка компиляции «освобождать нечего». То же для указателя на переменную:
`ptr p = &x; del p;` (и копии такого указателя, `ptr q = p; del q;`) — ошибка
компиляции. Проверка видит только присваивания в коде; указатель, пришедший
параметром функции, не отслеживается.

## 11. Строки

```sc
string s = "hello";
print(s);
print(len(s));
print(s == "hello");
print(s != "x");
string r = replace("a-b", "-", "+");
print(r);
print(str(42));
```
```text
hello
5
1
1
a+b
42
```

`len(s)` — длина строки, `s == t` — равны ли строки,
`replace(s, a, b)` — копия `s` с заменой `a` на `b`, `str(x)` — число в строку.
Строки сравниваются через `==` и `!=` (по содержимому). Сложение `+` пока не поддерживается.

`string` — отдельный тип (D-014, как в C++ и Rust): неявно в `ptr` не
превращается (`ptr p = s;`, передача строки в `fn(ptr)` — ошибка), `del` для
строки не пишется. `replace` возвращает только `string`; старая запись
`ptr r = replace(…)` + `del r` — ошибка компиляции с подсказкой.

Память строки освобождается сама (как `std::string` в C++ и `String` в Rust):
каждая string-переменная и каждый string-параметр владеет своей копией, и в
конце блока — в том числе при `return`, `break`, `continue` — она освобождается.
`string b = a` — копия: изменение `b` не меняет `a`. Функция получает копию
аргумента и возвращает вызывающему свою копию результата. `del s` и `drop s` для
строки — ошибки компиляции. Временная строка — результат `str()`, `replace`,
ввода, `read` или функции, не положенный в переменную (`print(str(1))`), —
освобождается в конце своего оператора (строки условия `while` — после каждой
проверки).

```sc
string a = "ab";
string b = a;
ptr p = data(b);
p[0] = 'X';
print(a);
print(b);
```
```text
ab
Xb
```

```sc-error
string s = str(1);
drop s;
```
```text
drop для строки не пишется: 's' — string, её память освобождается в конце блока
```

Перенос — явно, словом `move` со скобками (D-015): `string b = move(a);` отдаёт
память `a` переменной `b` без копии, после этого `a` использовать нельзя (ошибка
компиляции, как после `drop`), пока ей не присвоят новое значение. Перенос в
одной из веток делает имя непригодным и после `if`. Аргумент — только имя
string-переменной или параметра; `move` внешней переменной внутри цикла или
функции — ошибка (перенос выполнился бы несколько раз), кроме случая, когда тот же
оператор тут же присваивает этому имени новое значение: `s = f(move(s));`,
`q = enqueue(move(q), i);` в цикле можно (как в Rust; так же у структур и
растущих массивов). Записи `move a` без скобок нет.

```sc
string a = "abc";
string b = move(a);
print(b);
a = "new";
print(a);
```
```text
abc
new
```

```sc-error
string a = "abc";
string b = move(a);
print(a);
```
```text
'a' используется после move (строка 2)
```

Адрес символов строки берётся явно функцией: `data(s)` (как в C++) или
`as_ptr(s)` (как в Rust) — это одно и то же, результат — `ptr` на `char`.
Значок `&s` для строки — ошибка компиляции. `del` такого указателя — ошибка
«освобождать нечего», как для `&x`. Аргумент — строка с именем (переменная, параметр, поле): `data(str(1))` —
ошибка компиляции, временная строка умерла бы в конце оператора. Указатель
действителен, пока жива строка:
после конца её блока или нового присваивания строке он висячий (как в C++).

### Байт строки по номеру: s[i]

`s[i]` — байт строки с номером `i` (как `s[i]` в C++ и `s.as_bytes()[i]` в
Rust), тип — `byte` (`u8`), номер — от `0` до `len(s) - 1`. Буква и байт —
разные вещи (D-019): `"é"` — два байта, `len("é")` равно 2. С буквой-литералом
байт сравнивается сразу (`s[0] == 'h'`), с переменной `char` — через `(u8) c`.
Номер вне строки — ошибка выполнения `string index out of bounds`. Менять байт
через `s[i] = …` нельзя (ошибка компиляции); изменить — через `ptr p = data(s); p[i] = …`.

```sc
string s = "hello";

print(u[0]);
```

```text
195
```

```sc-error

```
```text

```

## 12. Ввод

`input_int("подсказка")` читает число, `input_str("подсказка")` — строку.

## 13. Файлы

`open(путь, режим)` открывает файл (`"w"`, `"r"`, `"a"`; не открылся — ошибка
выполнения; режим обязателен, `open(путь)` — ошибка компиляции), `write(f, строка)` пишет, `read(f)` читает следующую строку целиком (без `\n`;
в конце файла — пустую строку), `close(f)` или
`drop f` закрывает; после этого `f` использовать нельзя (ошибка компиляции, как
после `drop`).

```sc
file out = open("spec-file.txt", "w");
write(out, "строка");
drop out;
file inp = open("spec-file.txt", "r");
print(read(inp));
close(inp);
```
```text
строка
```

## 15. Встроенные функции

`sqrt`, `abs`, `pow`, `max(a, b)`, `min(a, b)`, `floor` (вниз), `ceil` (вверх),
`round` (округление), `rand()` (случайное целое), `len`, `replace`, `str`,
`data` и `as_ptr` (адрес строки, §11), `move` (перенос строки, §11).
`sqrt`, `floor`, `ceil`, `round` от целого аргумента дают `f64` (`sqrt(2)` —
`1.414214`). `pow(a, b)` от двух целых — целое, то же, что `a ** b`: выход за

Этими именами можно назвать свою переменную и свою функцию (как в C++ и Rust):
своя функция `fn int max(int a, int b)` заменяет встроенную во всей программе,
вызов `max(…)` идёт в неё. Ключевые слова и имена типов зарезервированы.

## 17. Известные ограничения

- Нет обобщённых типов, перечислений, `Option`/`Result`, сопоставления с образцом,
  замыканий, интерфейсов, пространств имён, многопоточности, FFI.
- `for x in p.scores` (поле-массив) и `for x in v[1..3]` (срез прямо в цикле), `pop()` у массива структур, `a[i].v.push(x)` и
  `a[i].v[j]` (поле-массив у элемента; пока через `P p = a[i];`), литерал-массив в
  аргументе `f([1, 2])`, срез поля-массива `p.scores[1..3]` и срез в переменной
  (время жизни окна — 5.2) — ещё не сделаны.
- Строка в элементе массива хранится копией и пока не освобождается (утечка, не
  порча памяти); строка в поле структуры освобождается вместе со структурой (§7).
- Сырой `ptr` не знает длину: индекс `p[i]` проверяется только на `null`.
- Адрес массива (`&a`) взять нельзя — ошибка компиляции.
- Модель памяти (автоматическое освобождение и проверки владения) ещё не сделана;
  `del` — ручной режим без проверок.
- Строки: нет `+`, сравнения `<` и `>`, обхода по буквам и работы с Unicode (байт по номеру `s[i]` — есть).
