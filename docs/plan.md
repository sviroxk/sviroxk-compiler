1. Одна задача — один небольшой PR `dev` → `main`. Сливать обычным squash, когда оба прогона `build-and-test` зелёные; после слияния выровнять `dev` = `main`. Никакого `--admin`; `.github/workflows/*` без владельца не трогать.

3. В каждом PR: `docs/spec.md` (если изменился язык), письмо (убрать сделанное, записать найденное), строка в конец `docs/progress.md`, решение владельца — в `docs/decisions.md`.
4. Владелец (Сэм) пишет по-русски и очень коротко. Ему — итог одной строкой после слияния: что теперь может программист.

Его обычный ответ — «оба способа». Что покрыто прежним ответом — не переспрашивать, распространить на соседние формы и сообщить одной строкой. Где C++ и Rust согласны — решать самому и сообщать.
6. Сайт `sviroxk/SC-DOC` не трогать: документация только в этом репозитории.
7. Перед остановкой (кончается ресурс): письмо и этот план обновлены и слиты, открытых PR нет, `dev` = `main`.

## Решения владельца, которые нельзя менять молча

Полный список — письмо, раздел «Решения владельца», и `docs/decisions.md`. Главное за 13.11:

- Строка — отдельный тип; `b = a` — копия; перенос только `move(a)` со скобками; адрес временной строки взять нельзя.
- Структура со строкой или списком внутри: `w = q` — полная копия, перенос — `move(q)`.
- Список в поле структуры: `clear` — пустой, можно добавлять (как в C++); `drop` — память возвращена, поле нельзя трогать до нового присваивания (как в Rust).
- Список в функцию — копия; отдать насовсем — `move(...)`, после него имя нельзя использовать до нового присваивания. Память списка возвращается сама в конце блока.
- `move(имя)` в цикле разрешён, только если тот же оператор даёт имени новое значение.
- Срез — оба способа: `v[1..4]` (конец не входит) и `slice(v, 1, 3)` (начало и количество); параметр-окно — `int[..] part` и `slice int[] part`; весь список можно отдать в окно без копии; выход за края — ошибка.
