## Решения, которые уже приняты (не пересматривать молча)

- Одно слово на одно действие. Нового слова-дубля не добавлять.
- Точные имена типов (`i32`, `f64`…) основные, короткие (`int`, `float`…) — алиасы; оба остаются.
- Целые: ошибка видна сразу; оборачивающий режим — позже, отдельным флагом. `-2 ** 2` = −4. Арифметика над `u8`/`i8` даёт `i32`.
- `defer` при `return`: сначала вычисляется значение, потом отложенные операции.
- `null` только для `ptr`; `Option`/`T?` — позже.
- `drop` только для динамических массивов и `file`; повторный `drop` и использование после — ошибка компиляции.
- `new int[n]` — массив длины n из нулей.
- Память: «как в Rust и в C++» — по умолчанию автоосвобождение и проверки владения, рядом ручной режим с сырыми указателями; сборщика мусора нет.
- Сборка остаётся `./build.sh` + `llvm-config`, без CMake.
- Код компилятора — C++20 (решение владельца 2026-11-12): новый код и рефакторинг пишутся на C++20; старый переводится на идиомы C++20 отдельными PR там, где это убирает код, копии или класс ошибок.
- LLVM: основная 23.1.5; 18–22 поддерживаются, их проверяет CI-матрица (`ci.yml`, PR #49; обязательная проверка `build-and-test`).

2. **Рефакторинг ядра, без новых возможностей.**
   - `sc::Type` вместо строк везде; убрать `normalize` из `semantic.cpp`.
   - Таблица встроенных функций вместо ключевых слов. Сейчас `len`, `open`, `read`, `write`, `close`, `rand`, `max`, `min`, `input_int`, `input_str` зарезервированы, и пользователь не может так назвать свою функцию.
   - Готово, когда все тесты зелёные и строковых типов в семантике нет.
3. **Библиотеки** (решение владельца 2026-11-12): extern-функции C + линковка (C++ — через обёртку `extern "C"`), имена модулей для своих библиотек; новые библиотеки не писать. Сначала дизайн-документ с вариантами синтаксиса — владельцу, код после его ответа. Подробно — `docs/backlog.md`, «Библиотеки».
4. **Хвосты.**
   - Динамический массив как аргумент функции (сейчас понятная ошибка компиляции: параметр `ptr` не знает длину).
   - Функция не может вернуть структуру.
   - Строки: `+`; `<` и `>` сейчас ошибка компиляции.
   - Формат ошибок лексера, позиция пропущенной `;`, сообщение для `1 < 2 < 3`.
5. **Модель памяти.**
   - Владение для `ptr`, строк и массивов; запрет возврата адреса локальной переменной.
   - Псевдонимы освобождённого массива сейчас не отслеживаются.
   - Решить дубли: `del` или `drop`; `close(f)` или `drop f`. `defer close(f)` вместе с `drop f` сейчас не ловится.
   - Готово, когда ошибки ловятся при компиляции и ASan на собранных программах чистый.
6. **Возможности, по одной за PR:** `enum` с данными и `match` → `Option`/`Result` и `?` → методы и интерфейсы → generics → UTF-8 → map/set → замыкания. Для каждой: раздел в спецификации, тесты на вывод и на ошибку, пример.
7. **Инструменты:** `sc fmt`, `-g`, `-O2`, затем LSP. Пакеты и конкурентность — после модулей с пространствами имён.

Стратегический план владельца из 7 этапов лежит в `docs/core-audit.md` §7; очередь выше его продолжает, а не заменяет.
